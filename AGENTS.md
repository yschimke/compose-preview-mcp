# AGENTS.md

This repository owns `compose-preview-mcp`, the local Model Context Protocol server for Compose
previews (`:mcp`), and the MCP App pages only it serves (`mcp-app/rc-viewer.html`,
`mcp-app/openai-probe.html`). Read `README.md` first; why this is its own repository, and what it
may depend on, is [`docs/design/MCP_REPOSITORY.md`](docs/design/MCP_REPOSITORY.md).

## Enforced rules

- Git history attributes work only to the human committer. Never add an AI `Co-authored-by:`
  trailer or use an agent identity as author/committer, in a commit or in a PR title or body.
  [`agent-attribution-scan.sh`](.github/scripts/agent-attribution-scan.sh) is the definition, run
  by the local hooks (`scripts/install-git-hooks.sh`) and the `No Agent Attribution` workflow.
  Deliberately **not** rejected: a `claude.ai/code` session link, the "🤖 Generated with …" and
  `_Generated by [Claude Code]_` footers, ordinary prose, and PR comments.
  `Yuri Schimke <yuri@schimke.ee>` is this repository's human identity; `github-actions[bot]` and
  `renovate[bot]` are exempt bot accounts.
- Branch names use `agent/...`.
- Commit subjects and PR titles use Conventional Commits; PRs are squash-merged and release-please
  reads the title.
- Run `./gradlew ktfmtFormat` before committing Kotlin; CI runs `ktfmtCheckAll`.
- **Never edit `mcp-app/compose-preview-viewer.html` or `mcp-app/preview-library.html`.** They are
  compose-preview-server's, copied byte for byte with `scripts/update-server-assets.py <tag>`, and
  CI checks them against `mcp-app/server-assets.provenance.json`. A change to either is a
  compose-preview-server release first.
- **Layer rule.** This repository is a layer-3 leaf (compose-ai-tools'
  `docs/design/REPOSITORY_LAYERS.md`): it may depend on published coordinates of the layers below,
  and nothing may depend on it as a coordinate. `:mcp` must not resolve `gradle-tooling-api`
  (`checkMcpToolingApiBoundary`).
- Immediately before every push, fetch `origin main` and confirm the branch or PR has not merged.
- Open or update a PR automatically after a completed coding change. Merge only when explicitly
  asked.

## Releasing

release-please cuts a draft release from the PR titles; `release.yml` attaches
`compose-preview-mcp-<version>.tar.gz`, the viewer and its provenance, then publishes it. The CLI's
`compose-preview mcp serve` resolves the newest release here. `release-please-config.json` carries
`"release-as": "4.0.0"` for the first release only; remove it once 4.0.0 is out.
